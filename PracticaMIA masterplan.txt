Stage 7 — Government Knowledge Engine
Tasks 44–51 · Transform verified government information into structured rules that PaperPilot can safely use.
Task 44 — Implement the official government source registry
Implementation: Codex develops a source registry containing approved government sources and their metadata. For each source, the system stores the official URL and issuing authority, jurisdiction and relevant procedure, language and document type, source and content version identifiers, retrieval and review dates, approval and validity status, and relationships to administrative requirements. The system distinguishes sources approved for retrieval from unreviewed or outdated material.

Deliverable: A source registry database, source management APIs, source approval and versioning logic, and metadata validation tests.

Completion: Sources can be registered, versioned, reviewed, retrieved, and invalidated without losing provenance.
Task 45 — Implement the RAG ingestion and indexing pipeline
Implementation: Codex builds the offline processing pipeline that converts approved government information into searchable knowledge. The work runs as six sequential subtasks. 45.1 Document collection: retrieve approved government webpages, PDFs, and supporting documents, preserve original content and metadata, and handle retrieval failures safely. 45.2 Content extraction: extract readable text from HTML and PDFs, and preserve headings, document structure, lists, tables where feasible, and references to original sections. 45.3 Document chunking: split extracted text into coherent passages based on document structure and topic boundaries, and preserve source IDs, document versions, section references, and relevant administrative metadata. 45.4 Embedding generation: generate embeddings for approved text chunks using the configured embedding model, and track model identity and embedding version so later reindexing stays possible. 45.5 Vector and keyword indexing: store text chunks and embeddings in PostgreSQL with pgvector, and configure keyword indexing with PostgreSQL full-text search and metadata indexes. 45.6 Index updates and synchronization: detect source changes, maintain versioned snapshots, and reindex changed content after the appropriate review. Outdated or unapproved sources must not silently replace trusted content.

Deliverable: A government document ingestion pipeline, text extraction and chunking services, an embedding generation service, PostgreSQL vector and keyword indexes, index synchronization and versioning, and automated ingestion tests.

Completion: Each subtask has its own verification before this task is complete. Approved government documents can be retrieved, processed, indexed, and updated reproducibly. Every stored passage retains its original source identity and evidence location.
Task 46 — Implement structured requirements with RAG evidence links
Implementation: Codex implements the structured administrative requirements database. Requirements include eligibility conditions, document obligations, deadlines, exceptions, and submission instructions. Each requirement references approved evidence passages rather than relying only on a general source URL.

Deliverable: Structured administrative requirements, links between rules and source passages, requirement versioning, and evidence-consistency validation.

Completion: Approved requirements load correctly and reference valid, traceable supporting sources.

Task 49 — Build the checklist generator

The system must distinguish automatically verified items from those awaiting user confirmation.

Deliverable: Checklist-generation service and persistent checklist data models.

Completion: Generated checklists match approved reference cases, change appropriately when relevant user information changes, and maintain consistent progress states.
Task 50 — Implement hybrid retrieval, reranking, and citation resolution
Implementation: Codex develops the runtime RAG retrieval service used by PaperPilot's AI agent. The service combines semantic and keyword retrieval, filters results using relevant administrative metadata, and returns structured evidence. The work runs as six sequential subtasks. 50.1 Query processing: interpret the retrieval request and extract procedure, municipality, administrative question, and language. 50.2 Metadata filtering: restrict retrieval to applicable jurisdictions, supported procedures, approved source versions, and valid content. 50.3 Semantic retrieval: search the pgvector index for passages semantically related to the question. 50.4 Keyword retrieval: use PostgreSQL full-text search for important exact terms, document names, identifiers, and administrative terminology. 50.5 Hybrid ranking and reranking: combine semantic and keyword results, remove duplicates, and rank relevant passages. Add a dedicated reranker only when retrieval evaluations show that it improves performance enough to justify its latency and cost. 50.6 Evidence and citation assembly: return selected passages with official source references, passage identifiers, document versions, and relevance information. The service distinguishes no evidence found, insufficient evidence, and conflicting evidence.

Deliverable: A hybrid retrieval service, metadata filtering, ranking and optional reranking, citation resolution, a structured retrieval API, and retrieval integration tests.

Completion: Each subtask has its own verification before this task is complete. The system retrieves relevant approved government passages and excludes irrelevant jurisdictions, revoked content, and unsupported procedures. Citations resolve to the appropriate source material.
Task 51 — Validate the complete government knowledge and RAG system
Implementation: Codex creates a benchmark collection of representative administrative questions and expected supporting passages. Retrieval evaluations include recall at K for expected supporting passages, ranking quality such as mean reciprocal rank, relevance of retrieved information, citation accuracy, correct jurisdiction filtering, behavior when evidence is missing, and handling of outdated or conflicting sources. The rules engine is evaluated against approved administrative scenarios.

Deliverable: A RAG evaluation dataset, an automated retrieval benchmark runner, an administrative rules test suite, and a performance and failure-analysis report.

Completion: Retrieval and rules tests meet approved acceptance thresholds. Critical source-filtering and evidence-traceability failures are resolved.

Execution and dependency rules
The original task IDs remain unchanged. New subtasks execute in order. Task 45 runs 45.1, then 45.2, then 45.3, then 45.4, then 45.5, then 45.6. Task 50 runs 50.1, then 50.2, then 50.3, then 50.4, then 50.5, then 50.6. Each subtask has its own verification before the parent task is complete.

Task 45 requires the approved source registry from Task 44. Task 46 uses the approved evidence references and document models. Task 50 requires indexed government content from Task 45. Task 51 requires functional retrieval and deterministic rule evaluation. Task 53 requires the validated knowledge engine. Task 56 integrates the completed retrieval and rules APIs. Task 60 verifies the integrated agent before document intelligence development continues. Task 80 performs comprehensive release-level grounding validation.

Task IDs not updated in this RAG revision retain their previous descriptions and acceptance criteria.

The RAG system must not index private uploaded user documents into the shared government knowledge base. Government knowledge retrieval and personal document processing remain separate services with independent access controls.
