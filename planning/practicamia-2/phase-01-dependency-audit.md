## Verification and cleanup order

- Inventory completeness was checked against `git ls-tree -r --name-only d955e79`. Each path has one disposition and a group listed above. Direct source searches, Python AST parsing, route decorators, Next handler paths, build file readers, and workflow invocations were used to corroborate the map.
- Task 3 should examine source versions and approval records before moving documented evidence. Checked-in source metadata and review records do not establish the contents of hosted databases or buckets. Task 1's Git archive is the code fallback. Database rollback remains separate.
- Task 4 can replace documentation and governance as one change set. Task 5 can remove the Milan UI and adapters after the shared dependency edges have explicit replacements. Task 6 can verify each retained component with isolated contracts before package pruning.
- Runtime verification in this PR is the unchanged application test configuration and the PR checks. Static references do not rule out external callers. Standalone APIs, opt-in workflows, and hosted configuration require their own evidence before removal or release.
