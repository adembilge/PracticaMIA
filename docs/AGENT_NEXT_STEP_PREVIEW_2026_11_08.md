# 8 November 2026 — Case-aware LangGraph guide increment

## Scope

This change extends the existing **synthetic-only**, authenticated Preparation Preview
route `POST /api/v1/cases/{case_id}/preparation/guide`. It does not introduce a
new production API, migration, deployment, credential, municipal rule, or source
approval. It does not alter the signed Milan catalog.

## What changes

- The one-turn LangGraph selector recognizes five bounded actions:
  `intake`, `evidence`, `case_status`, `documents`, `next_step`.
- A model may select an allowed action label; otherwise a deterministic,
  English/Italian keyword router is used.
- `next_step` first checks the existing five-question product scope.
  When information is missing, it returns the next typed question without
  invoking preparation tools. Unsupported scope does not become official
  ineligibility or invoke application preparation.
- For a complete candidate scope, `next_step` obtains a **fresh** server-side
  preparation assessment. Its `next_action` is derived from approved-rule
  evaluation and document review, not generated by the model.
- `documents` gives a redacted document-review status from the existing
  authenticated preparation assessment. No document text is passed to
  the model or included in the assistant response.
- The guide's previous hardcoded statement that all rules are still awaiting
  approval has been replaced with wording that reflects runtime approval checks.

All read tools retain their existing case-ownership, approved-passage, and
current-rules enforcement. The guide cannot save case facts, approve fields,
approve a package, perform an official submission, or activate a catalog.

## Test coverage and validation

Regression tests cover no-model next-step selection, early-stop on missing
facts, unsupported scope, runtime blockers, reviewable-package directions,
read-only document conflicts, forbidden model actions, and the authenticated
owner-scoped Preview route. These are **synthetic tests**, not proof of a
live-model or real-person end-to-end workflow.

Run: `cd backend && python -m pytest -q tests/test_preparation_agent.py tests/test_preparation_api.py`.
Full repository backend and frontend checks run on the PR's GitHub Actions.
No Vercel deployment is required to assess this change.
