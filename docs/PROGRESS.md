The [message acceptance service](../backend/app/agent/run_requests.py) adds encrypted request persistence and durable queued run IDs. Identical retries recover the same run, and new requests respect the thread revision and one-active-run invariant. A cascaded case or thread deletion removes its saved requests. Migration `20261118_0019` is additive. Worker execution checkpoints, live event resumption, and hosted message routes remain open.

The [run event journal](../backend/app/agent/run_events.py) stores encrypted events and state transitions atomically. Its cursor reader can recover missed events from a new database session. Local checks cover rollback, replay, terminal state, ownership and ciphertext integrity. PostgreSQL CI covers concurrent event retries and deletion cascades. Migration `20261118_0020` is additive. Live HTTP resumption remains open.

The [worker checkpoint service](../backend/app/agent/checkpoints.py) stores an encrypted next-node state, procedure/location candidates and bounded references. A worker can reload the last consistent checkpoint in a new database session. Stale writes are rejected, and a checkpoint and its optional event are committed together. Migration `20261118_0021` adds the checkpoint table and cascading removal with its run. Live worker scheduling, retention and pilot approval remain open.

The [internal worker](../backend/app/agent/worker.py) loads a saved checkpoint, executes a read-only graph invocation and advances the checkpoint and event journal. A terminal answer is committed against the same revision and watermark, then clears its checkpoint. The [synthetic recovery test](../backend/tests/test_agent_worker.py) interrupts a step and continues with a new session factory. The case-free [LangGraph graph](../backend/app/agent/chat_graph.py) now handles intent, location clarification/resumption and approved-only reference retrieval for the Milan pilot. LLM-backed answer generation, reviewed service-area assignments and the approved multi-authority pilot remain open.

The [worker queue](../backend/app/agent/worker_leases.py) selects eligible runs using a database lease. It skips rows held by another claimer, reclaims expired leases and rejects results from workers that lose ownership. The chat-only invocation can claim only unlinked conversation runs and leaves legacy case-linked rows untouched. Migration `20261118_0022` adds the lease fields and queue index. Hosted dispatch and LLM-backed reviewed-source execution remain open.

The [worker clarification path](../backend/app/agent/worker.py) stores the pending question and resume checkpoint in one transaction, then releases the worker lease. A new session can replay the question from its last event cursor. Synthetic tests cover lease release, queue exclusion while waiting and rollback on invalid output. The [internal clarification reply service](../backend/app/agent/checkpoints.py) now validates thread and case ownership, question ID, expected run revision and answer shape. It commits the encrypted reply and checkpoint together. The next worker step receives the original message and the saved reply, and an identical retry at the same question boundary returns the stored event. Local tests cover invalid choices, stale and foreign requests, ciphertext and resumed execution after interruption. The disposable PostgreSQL test exercises simultaneous identical replies. The [isolated HTTP test](../backend/tests/test_agent_reconnect_http.py) uses signed JWTs to discover active runs, read a run snapshot, replay an event cursor, send an idempotent clarification reply, and recover the terminal answer. Discovery pages contain only run metadata. Tests cover ordering ties, continuation after a run finishes, and owner and case boundaries. It checks foreign and deleted runs, invalid replies and private cache headers. The default and production application configurations keep these routes absent; only the pinned isolated Preview gate can register them. The [local Chromium scenario](ACCEPTANCE_TESTING.md#acceptance-scenarios) also exercises discovery from a fresh browser context, a lost reply response followed by an identical retry, second-account isolation, and retrieval of the completed fixture result. The [worker batch service](../backend/app/agent/worker.py) limits the number of attempts in each invocation and stops when the queue is idle. A lost lease uses one attempt. The localhost bridge polls the queue with a deterministic executor. Chromium verifies that a saved reply becomes a completed run through this background worker. Hosted deployment and worker scheduling remain open.

Chromium checks that the stopped run is absent from active discovery after reload. Hosted transport and reporting for future committed case writes remain open.
